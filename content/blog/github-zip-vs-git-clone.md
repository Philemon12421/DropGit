Every GitHub repository page gives you two obvious ways to get the code onto your computer: **Download ZIP** and **git clone**. They look similar from the outside, since both leave you with a folder of files, but they are built for different jobs. Picking the wrong one is a common source of confusion, such as "why does my downloaded folder say it is not a Git repository?".

## What a ZIP download contains

A ZIP archive is a snapshot. It holds the files as they exist on one branch, tag or commit and nothing else. There is no history, no record of who changed what, and no connection back to GitHub.

- **No `.git` folder.** Git commands such as `git log` or `git pull` will not work inside the extracted folder.
- **Smaller size.** Because history is left out, the download is usually far smaller than a full clone of an old, busy repository.
- **No account or tools needed.** You can open the archive on any computer.
- **Some content is excluded.** Files marked `export-ignore` in the repository's `.gitattributes` are left out, submodule contents are not included, and Git LFS files appear as small pointer files rather than the real large files.

## What git clone gives you

Cloning copies the repository database itself, including the commit history of every branch you fetch, and sets up a link to the original (called a remote) so you can fetch updates.

- **Full history.** You can browse old versions, find when a bug was introduced, or restore deleted files.
- **Easy updates.** `git pull` brings in new changes without downloading everything again.
- **Contributing is possible.** You can create branches, commit, and push to your own fork.
- **More disk space and time.** Large repositories can take a while to clone. A shallow clone with `--depth 1` shortens this by fetching only the latest commit.

## Side-by-side comparison

| | ZIP download | git clone |
| --- | --- | --- |
| Needs Git installed | No | Yes |
| Includes history | No | Yes |
| Can pull updates | No | Yes |
| Typical size | Smaller | Larger (unless shallow) |
| Best for | Reading, trying, one-off use | Developing, contributing, long-term use |

## Which should you choose?

Choose a **ZIP** when you only want to look at the code, grab a template, or copy a few files and you do not plan to follow upstream changes. Choose a **clone** when you will keep working with the project, want to contribute, or need the history.

There is also a middle path. If you only need part of a large repository, you do not have to download all of it either way. You can use a folder downloader or Git's sparse-checkout, both covered in [How to download a single folder from GitHub](/blog/how-to-download-a-single-folder-from-github).

## Common questions

**Can I turn a ZIP back into a Git repository?** You can run `git init` in the folder and start a new history, but it will not be linked to the original project's commits.

**Is a ZIP download safe?** The archive is generated by GitHub from the repository content, but as with any code you did not write, read it before running it, especially install scripts.

**Why is my ZIP missing some files?** The usual causes are `export-ignore` rules, submodules, and LFS pointer files, as described above.
